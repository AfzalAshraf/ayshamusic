# Android icons and signed updates

Settings offers eight native launcher aliases. Switching enables the new alias before disabling the others; Android 13+ applies the change atomically. Some launchers cache shortcuts. The default remains the existing rose-heart design. `android-app/tools/generate_icon_picker.py` regenerates the checked-in raster resources from the committed artwork (Pillow required). The transparent embossed original is composited on a neutral launcher background; Android launcher icons themselves cannot be literally background-free on every launcher.

The updater checks the official GitHub latest release when the app is open/resumed (at most once per day automatically) and, if enabled, downloads on an unmetered Wi-Fi connection. It does not currently schedule a background job while the app is closed. Downloads are size-bounded, hash-checked and inspected for package, newer version, ARM64 backend and the exact installed signing certificate; a different signer is rejected. Android's package installer performs its own verification and asks the user to confirm. Permission to install from this app must be granted in Android settings. No uninstall or data clear is performed. A preview signed with a different key cannot safely become a production update, and this feature does not establish which key signed an existing phone installation.

## Publishing gate (off by default)

On pushes to main, production publication happens only if repository variable `AYSHA_RELEASE_ENABLED` is `true`, both the APK build and offline Android emulator job pass, and the repository signing configuration is valid. Use GitHub's protected secret/variable settings, never chat or source files. Configure secrets `AYSHA_KEYSTORE_BASE64`, `AYSHA_KEYSTORE_PASSWORD`, `AYSHA_KEY_ALIAS`, and `AYSHA_KEY_PASSWORD`; configure variable `AYSHA_SIGNING_CERT_SHA256` with the lowercase SHA-256 fingerprint of the **same certificate as the installed app**. Confirm that continuity independently on an actual device before enabling release publication. No original key is currently known. A new signer cannot upgrade an installation signed by another key; do not uninstall the old app to work around that.

The workflow verifies the single APK signer against the pinned fingerprint, versions builds as `1000 + GitHub run number`, runs offline checks, and publishes an immutable `android-v<code>` release with the APK and bounded `update.json` only if the tested SHA is still main. An empty/missing or wrong key/fingerprint fails closed. GitHub runs, versions and fingerprints are not proof of phone playback, Telegram preservation or update installation. Manual and PR runs remain explicitly labelled preview artifacts and never publish. Older `apk-latest` assets are not update manifests and are not accepted by the updater.
